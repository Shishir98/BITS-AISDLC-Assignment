# Clarification Decisions: Natural-Language Reminder Agent

**Date**: 2026-11-19
**Source**: Owner-provided feature and local Ollama architecture decisions

No product-scope question remains unanswered. The decisions below record the
owner-approved local-runtime, evaluation, and privacy boundaries.

| ID | Topic | Decision | Rationale |
|---|---|---|---|
| CD-001 | Reference time | Every interpretation request supplies an offset-aware reference datetime; the service never substitutes the host clock. | Relative dates must be reproducible and testable. |
| CD-002 | Timezone | Every request supplies a valid IANA timezone; the response echoes that identifier. | The service has no user profile from which to infer a zone. |
| CD-003 | Future boundary | A ready scheduled instant must be strictly later than the reference instant; equality is not future. | Removes boundary ambiguity and prevents immediate/past actions. |
| CD-004 | Bare weekday | A bare weekday means its next occurrence strictly after the reference local date. “This <weekday>” means the current local week only if that date is not past. | Defines a deterministic default; past interpretations clarify rather than roll forward. |
| CD-005 | Daylight-saving transitions | A nonexistent or repeated local wall time is not actionable unless the request disambiguates the instant. | Avoids silent time normalization or arbitrary fold selection. |
| CD-006 | Partial results | Clarification responses may retain a recognized intent and concise questions, but never include `scheduled_at` or have actionable status. | Preserves useful classification without presenting an incomplete proposal as ready. |
| CD-007 | Inference runtime | Ollama local HTTP API is the sole inference runtime; use one locally installed model and no cloud models or cloud inference. | The owner explicitly selected on-device/local model inference. |
| CD-008 | Runtime configuration | `OLLAMA_BASE_URL` defaults to `http://127.0.0.1:11434`; `OLLAMA_MODEL` defaults to `qwen3.5:9b`; `OLLAMA_TIMEOUT` defaults to 120 seconds; `MODEL_TEMPERATURE` defaults to 0.2; `MODEL_TOP_P` defaults to 0.9; `MODEL_CONTEXT_LENGTH` defaults to 4096. All are configurable. No API key is required. If the selected model is missing, evaluation blocks and gives the exact `ollama pull qwen3.5:9b` recovery command; the application never downloads or substitutes a model. | Records the implementation-specific defaults selected by the owner while preserving the local-only design. |
| CD-009 | Local-only guard | Set `OLLAMA_NO_CLOUD=1` in the Ollama server process environment and restart Ollama. Evaluation verifies that actual process configuration and the selected model in the actual local inventory; remote-model metadata is rejected. A localhost application URL alone is insufficient evidence. An explicitly configured non-loopback endpoint is warned and marked outside normal local-only mode. | Prevents accidental cloud inference while making configuration and endpoint mode verifiable. |
| CD-010 | Structured output | Pass the response JSON Schema to Ollama structured output where supported and include requirements in the system prompt; independently validate all output with Pydantic. | Model-side constrained generation does not replace application validation. |
| CD-011 | Failure handling | Use distinct runtime/application codes: `OLLAMA_UNAVAILABLE`, `MODEL_NOT_INSTALLED`, `INFERENCE_TIMEOUT`, `INVALID_MODEL_OUTPUT`, and `APPLICATION_ERROR`. Infrastructure errors do not count as semantic failures. | Avoids fabricated success and makes evaluation failures diagnosable. |
| CD-012 | Evaluation runs | Use the 19-case baseline distribution (5 representative, 4 boundary, 4 ambiguous/missing, 2 malformed-language, 4 adversarial/guardrail); run each case three independent times against actual local inference, for exactly 57 generations. Keep parameters unchanged, record genuine output differences, and use no mocked final evidence. | Measures actual model behavior reproducibly without manufactured variation. |
| CD-013 | Evaluation provenance | Preserve Ollama version, verified server-process cloud configuration, actual local model inventory, model ID/digest/details, prompt version/digest, actual generation parameters including temperature/top-p/context length and `think: false`, `ollama ps` GPU/CPU offload observation, dataset digest, fixed temporal input, and each individual generation under Part-1B `evidence/evaluations/`. | Supports review and repeatability without retaining data in the application. |
| CD-014 | Privacy | The application sends requests only to its configured Ollama endpoint, adds no telemetry/analytics/remote logging, and persists no requests or results. The evaluation harness may preserve actual generations as assignment evidence. | Enforces local privacy while meeting evaluation evidence needs. |
| CD-015 | Dataset and harness locations | The single evaluation dataset is `evals/dataset.json`; the single integrated runner is `.harness/run_evaluation.py`. These exact assignment paths replace the earlier `evaluation/cases.jsonl` and `evaluation/run_evaluation.py` paths in the plan/tasks. | Prevents duplicate datasets and multiple top-level evaluation commands. |
| CD-016 | Property-score weighting | Calculate non-critical property/invariant pass rate for each case-run, then average the case-run rates equally across completed case-runs. Critical invariants remain a separate 100% gate. | Prevents cases with more assertions from dominating the score, while preserving all approved thresholds. |
| CD-017 | Runtime verification evidence | The controlled Ollama launcher records that it set `OLLAMA_NO_CLOUD=1` before launching `ollama serve`; evaluations also verify the actual local `/api/tags` inventory and capture `ollama ps` where available. A localhost URL alone is never treated as proof of local-only operation. | Makes the server-process setting and real local runtime evidence reviewable. |
| CD-018 | Invalid request response | HTTP 422 request-envelope validation uses `INVALID_REQUEST`; it is separate from the five Ollama/runtime/application error outcomes. | The existing OpenAPI contract declared a 422 response but its error enum contained only runtime/application errors; a distinct client-input code avoids misclassifying invalid requests. |
| CD-019 | Model thinking mode | For the selected Qwen3.5 model, send `think: false` to Ollama so internal reasoning does not exhaust the context needed for the structured response. Keep temperature, top-p, context length, timeout, model, dataset, and thresholds unchanged; record the request field in each evaluation manifest. | The latest failed runs contained empty outputs with `done_reason=length`; local `/api/show` confirmed that this model supports both thinking modes. |

The exact model identifier is deployment configuration and must be installed before
evaluation. No API key, additional approval register, bootstrap system,
evidence-signing system, or protected-runner requirement is needed.
